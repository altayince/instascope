# Browser-local public-photo upscaling (INS-82)

**AI upscale 4×** is an optional, explicitly general-purpose Real-ESRGAN operation in a dedicated browser worker. Face-specific restoration is **not available** in the product: see the [face-model evaluation and measured blockers](PROFILE_AI_AUDIT.md). This is not a silent fallback from a face model. Original comparison, cancel, progress and PNG download remain available. No photo or archive is uploaded for enhancement; model/runtime downloads are from this site's origin. Public-photo lookup remains the separate, credential-free Worker with its existing rate limits.

The model estimates plausible detail and can alter facial features. The output is explicitly **AI-upscaled**, never Instagram's original HD photo. Small faces may remain soft. Actual dimensions are shown and included in the download filename: 150×150 → 600×600; 320×320 → 1280×1280; 48×32 → 192×128. There is **no source downscale and no final canvas interpolation**. PNG encoding uses `putImageData` at the model's native dimensions; preview zoom is separate.

Sources up to 1024px per side are accepted. At most 270px per side goes through inference at once. Larger sources use 192px cores with 36px neighboring halos, retaining the learned core pixels in their original positions. The pinned graph has 34 consecutive 3×3 convolutions before pixel shuffle; the halo exceeds its source receptive-field radius. Only artificial internal tile boundaries are discarded. No blending, resizing or face-specific processing occurs. The benchmark compares tiled 320px output against whole-frame inference and rejects differing seams. One session serves all tiles; tensors are disposed between runs. Output is bounded to 4096px per side and still consumes memory independently of the bounded inference tiles.

The optional action does not load model/runtime assets on initial page load. First use downloads approximately 19.1 MB (18.2 MiB) for the model, WASM and loader, plus the application's JS. Larger images take substantially longer, especially on phones; per-tile progress, cancellation and a three-minute deadline keep the original available. A CDN denying anonymous CORS access also leaves the original intact. Browser capability alone does not establish physical iPhone memory safety or photographic restoration quality.

## Provenance and distribution

- Upstream: [Xintao Wang's Real-ESRGAN](https://github.com/xinntao/Real-ESRGAN), `realesr-general-x4v3`, release `v0.2.5.0`, BSD-3-Clause. Source weights SHA-256: `8dc7edb9ac80ccdc30c3a5dca6616509367f05fbc184ad95b731f05bece96292`.
- ONNX conversion: [SkillSafe's reproducible model export](https://huggingface.co/skillsafe-ai/realesr-general-x4v3/tree/042a40bc4c918349ad3e2e607a68ae509a4c27b5), pinned revision `042a40bc4c918349ad3e2e607a68ae509a4c27b5`. Its manifest records the source weights, conversion recipe, tools and comparison against the PyTorch reference. The FP32 model has RGB float32 NCHW input in [0,1], a four-times output and opset 17.
- Committed ONNX artifact: 4,866,428 bytes, SHA-256 `a946f7a9397021b9b6b7e71df3d2821b04cc09ff244423b7ca79cb191ce4a00e`. Build and browser worker both verify this digest; an unexpected model fails closed. The upstream BSD notice is distributed in `public/profile-ai/LICENSE.txt`.
- Runtime: Microsoft's `onnxruntime-web` **1.30.0**, pinned in package/lock, MIT notice in `public/profile-ai/ONNXRUNTIME-LICENSE.txt`. Build hooks copy only matching single-thread SIMD WASM and its loader into the ignored `public/profile-ai/runtime/1.30.0/` directory. Each served file is below Cloudflare's 25 MiB asset limit; the largest is the 14,239,897-byte WASM file. No external CDN is needed at runtime.

`npm run dev`, `npm run build` and `npm run build:production` prepare/verify these assets automatically. Runtime changes require updating and reviewing the pinned version and copied assets. Model changes require a reviewed artifact, provenance/licence and digest update; do not fetch unpinned models at build/runtime.

The CSP adds **wasm-unsafe-eval** solely to allow WebAssembly compilation; JavaScript `unsafe-eval` remains disallowed. Same-origin connection/script/worker restrictions and CDN image validation remain. Single-thread WASM in a dedicated worker needs no cross-origin isolation or SharedArrayBuffer. The local preview serves WASM/MJS with the correct MIME types and applies the production CSP so browser tests exercise these restrictions. See [ONNX Runtime deployment guidance](https://onnxruntime.ai/docs/tutorials/web/deploy.html).

## Reproducing the local benchmark

With dependencies and Playwright Chromium/WebKit installed, run `node scripts/benchmark-profile-ai.mjs`. It reads only repository-created fictional SVG fixtures, serves a whitelisted set of resources on loopback, and uses the actual worker/model. No external inference or public-profile lookup occurs. Output PNGs, comparison images and JSON metrics are written under ignored `.tools/profile-ai-benchmark/`. Playwright additionally attaches source/output PNGs, timings and controls screenshots for the 150px portrait, 320px portrait and non-face logo in both projects.

WASM metrics measure allocated linear memory. On Windows the dedicated benchmark browser's process tree is sampled every two seconds for an **observed** working-set peak, including the browser baseline. Sampling can miss brief peaks; neither metric is an exact cross-platform maximum. Device descriptors change viewport/user agent, not the physical CPU or iOS memory limits.
