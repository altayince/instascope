# INS-98 — Product UI refresh

This refresh makes the loaded workspace easier to navigate and inspect while keeping InstaScope's paper background, forest-green ink, restrained lime accents and editorial typography. Existing tools, export formats and public destinations remain in place.

## Responsive and accessibility review

Reviewed desktop Chromium (1280 × 720), Pixel 7 (393 × 851 CSS px), tablet (820 × 1180) and a narrow iPhone-like viewport (375 × 812). The automated capture checks document overflow on every surface, menu bounds and sheet bounds. Long normalized usernames are included in the drawer regression fixture.

Native buttons, links, disclosure menus and dialogs remain semantic. Active destinations use `aria-current`; selected controls also use text and pressed states. Drawer section headings follow its dialog title, the open control identifies dialog behavior, focus is visible, modal background content stays inert and closing restores the originating control without scrolling. Reduced-motion behavior is used for deterministic keyboard and geometry checks.

Screenshot review prompted concrete corrections: put Overview results before discovery cards, make the last mobile metric compact across both columns, keep drawer close/actions outside its scrollable content, and retain native focus movement for same-page insight links.

## Preserved boundaries and remaining limitations

Parsers, normalization, relationship/history/context calculations, dataset/provider storage, Vault schema and persistence transactions are unchanged. Dashboard insights compose the existing models; they do not infer intent, loyalty, rename identity, exact change times or continuous observation. No dependencies, paid services, archive transmission or new retained review state are added.

Real saved history still requires explicit same-account confirmation. Earlier-context claims still require an active export date and strictly earlier observations. Missing categories and dates retain their factual states. Demo uses only fictional history; private lists do not enter Wrapped/share output. Comparison and saved-only rows retain snapshot semantics rather than opening an inspector for the unrelated active export.

Public routes, titles, H1 intent, descriptions, canonical/OpenGraph URLs, sitemap registration and robots rules are unchanged. Dashboard and Vault remain `noindex, follow` in production; preview builds remain `noindex, nofollow` with a blocked robots file and empty sitemap.

WebKit mobile tests emulate an iPhone; physical iPhone/Safari hardware is unavailable in this environment. Private account fragments remain in local browser history, so users should still treat their local workspace as private. The public Profile Viewer continues to depend on Instagram's public availability and existing rate limits; this UI refresh does not change its retrieval or enhancement pipeline.
